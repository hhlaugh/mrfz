# 多棋盘攻防卡牌游戏规则 v0.8

> **文档状态：统一规则基线，待引擎实现与对局平衡测试**  
> **替代版本：v0.7**  
> **本版原则：所有模式使用同一套规则引擎。棋盘布局、卡池、牌组、数值和胜负参数均通过数据配置；不得为 Demo、标准棋盘、DIY 棋盘建立互相分叉的战斗规则。**

## 0. v0.8 变更摘要

1. 保留 v0.7 的费用、抽牌、疲劳、回合、撤离/快速撤离/强制撤离、退款、再部署 CD、SP、冰冻/眩晕等基础机制。
2. 将固定“三路、前后排各一格”改为 `BoardProfile` 数据配置；标准棋盘仍为 3 路、每路前排 1 格、后排 1 格。
3. 增加紧凑、标准、宽幅、扩展四种默认棋盘；所有默认棋盘共享同一经济规则，不做独立费用、退款、CD 或资源增益补偿。
4. 增加每方独立的路数、每路前后排格数，以及非对称棋盘和路线分组；第一版 DIY 编辑器限制为每方最多 6 路、每排最多 4 格、总卡位最多 24 格。
5. 增加攻防模式：双方基地 HP 可独立设置，回合上限按“完整轮次”计数；守方存活至回合上限即获胜。
6. 同一路多卡位的行动顺序、受击选择和范围效果顺序采用稳定的路序、排序和卡位序，不依赖对象创建顺序或浏览器渲染顺序。
7. 嘲讽、浮空、被动光环等可压制的持续效果改为数据化；沉默可压制 `persistent_effects_json` 中标记可沉默的效果。基础数值与非技能固有属性不受沉默影响。
8. 正式定义 `silence`：沉默期间不能触发目标自己的技能或可沉默持续效果，但普通攻击和全部 SP 获取仍可正常进行；已有 SP 与已结算状态不清除。
9. 为范围攻击、治疗和辅助效果统一目标范围、目标数量、筛选条件、选择优先级和目标快照规则。
10. 增补 `on_attack_declared`、`on_attack_resolved`、`on_friendly_attack_declared` 及 `continuous` 条件检查；补齐 `if_else` 原子分支等 v1.1 卡池依赖。
11. v1.1 干员卡池仍属于待引擎兼容和模拟平衡的卡牌数据，不代表其所有效果已经在当前 Demo 中实现。

## 1. 核心目标与术语

玩家通过部署干员、使用战术卡、装备支援、发动技能和调整阵线，在由棋盘配置定义的一条或多条路线中争夺空间，最终摧毁敌方基地或达成对应模式的胜利条件。

| 中文标准术语 | 英文/代码 | 定义 |
|---|---|---|
| 基本分 | Base Points / `base_points` | 玩家基地耐久；降至 0 或以下即失败 |
| 生命值 | HP / `hp`, `current_hp` | 干员生命；不用于表示基地耐久 |
| 攻击力 | ATK / `atk`, `current_atk` | 干员攻击数值 |
| 费用 | Cost / `cost` | 玩家公共资源；卡牌印刷费用也用此字段 |
| 实际支付费用 | Paid Deploy Cost / `current_deployment_paid_cost` | 最近一次部署实际扣除的费用，作为撤离退款基数 |
| 技力 | SP / `current_sp` | 干员个人技能资源 |
| 行动阶段 | Action Phase / `action` | 部署、使用卡牌、技能及撤离的阶段 |
| 战斗阶段 | Combat Phase / `combat` | 当前回合玩家的干员自动普通攻击阶段 |
| 普通撤离 | Normal Withdrawal / `normal_withdrawal` | 玩家在行动阶段执行的基础撤离操作 |
| 快速撤离 | Rapid Withdrawal / `rapid_withdrawal` | 0 费战术卡；全额返还部署费用并减少此次撤离 CD |
| 强制撤离 | Forced Withdrawal / `forced_withdrawal` | 由明确的卡牌或效果执行，可按字段豁免普通撤离限制 |
| 再部署冷却 | Redeploy CD / `redeploy_cd_remaining` | 卡实例尚需跳过的后续己方行动阶段数 |
| 嘲讽 | Taunt / `taunt_scope` | 提高合法攻击者对指定嘲讽单位的普通攻击目标优先级 |
| 浮空 | Floating / `floating` | 后排专属原生词条；近战普通攻击不能选中，不拦截基本分攻击 |
| 落地 | Grounded / `grounded` | 暂时取消浮空，使其作为后位地面单位参与目标选择 |
| 眩晕 | Stun / `stun` | 禁止普通攻击和主动技能，并失去拦截资格 |
| 冰冻 | Freeze / `freeze` | 更强控制；封锁事件型技能与所有 SP 获取，并失去拦截资格 |
| 拦截资格 | Interception Eligibility / `intercept_eligible` | 根据位置及状态实时计算的结果，不是可任意设置的基础属性 |
| 所属半区 | Board Half / `board_half` | 干员当前所在棋盘半区 |
| 棋盘配置 | Board Profile / `board_profile` | 对局开始前确定的棋盘布局、路线分组与胜负参数 |
| 路线分组 | Route Group / `route_group_id` | 将双方一个或多个物理路连接起来的攻防通道集合 |
| 卡位 | Slot / `slot_index` | 某一路前排或后排中的具体部署位置，按 1 起始编号 |
| 永续效果 | Persistent Effect / `persistent_effects_json` | 由卡牌持续提供、可按压制规则暂时失效的关键词、光环或被动修正 |
| 沉默 | Silence / `silence` | 禁止目标触发自身技能，并压制标记可沉默的永续效果；不阻止 SP 获取 |
| 攻防模式 | Siege Mode / `siege` | 双方布局、基地 HP 和路线可以非对称，带完整轮次上限的特殊模式 |

**字段区别必须保持：** `cost` 是卡牌印刷费用；`current_deployment_paid_cost` 是本次部署实际支付费用；`sp_cost` 是技能消耗的技力。三者不得混用。

## 2. 棋盘与部署

### 2.1 棋盘由配置决定

棋盘不再由规则引擎写死为三路。每场对局开始时加载一份不可变的 `BoardProfile`，至少包含：

- 双方各自的路列表及 `lane_order`；
- 每一路的 `front_slots`、`back_slots`；
- 双方路之间的 `route_groups` 连接关系；
- 双方基地 HP；
- 模式与胜负参数（例如是否有 `round_limit`）。

每个物理卡位由 `(side_id, lane_id, row, slot_index)` 唯一定位。`row` 只允许 `front` 或 `back`；`slot_index` 从 1 开始。卡位编号在每一路的每一排内独立编号。

### 2.2 默认棋盘预设

| `board_id` | 路数 | 每路前排 | 每路后排 | 双方基地 HP | 用途 |
|---|---:|---:|---:|---:|---|
| `compact_2x1x1` | 2 | 1 | 1 | 20 | 紧凑短局与小规模测试 |
| `standard_3x1x1` | 3 | 1 | 1 | 20 | 标准规则基准，沿用现有 Demo 棋盘 |
| `wide_3x2x1` | 3 | 2 | 1 | 20 | 增加前排阵容与拦截组合 |
| `extended_4x2x1` | 4 | 2 | 1 | 20 | 多路线与大规模阵容 |

上述预设只改变布局，不改变每回合费用增长、费用上限、部署费用、普通撤离退款、快速撤离返还比例、再部署 CD、自然 SP 回复或其他经济规则。**不得按棋盘大小自动增加费用、退款、部署次数或 CD 减免。**

### 2.3 DIY 棋盘与合法性边界

DIY 棋盘允许玩家分别编辑双方布局，不要求对称。第一版编辑器建议限制：

- 每方 1–6 路；
- 每一路前排 0–4 格、后排 0–4 格；
- 每一路前后排合计至少 1 格；
- 每方总卡位不超过 24 格；
- 每个路线分组在双方至少各连接 1 路；
- 每方每一路必须且只能属于一个路线分组。

以上是第一版编辑器的产品与性能边界，不是战斗平衡机制。数据加载器仍须独立校验，不能只依赖 UI 限制。

### 2.4 路线分组 `route_groups`

当双方路数不同，物理路之间通过路线分组连接。一个分组可以包含一侧多路、另一侧一路，或双方多路。例如攻方 A1、A2 连接守方 D1；攻方 A3、A4 连接守方 D2。

- 普通攻击只能选择攻击者所在物理路所属路线分组另一侧的目标。
- 同一分组内，多个敌方物理路均属于该攻击者的可选目标集合；一个攻击者每个战斗阶段仍只进行一次普通攻击，不会因连接多路而重复攻击。
- 选择目标时，先按目标类别优先级，再按敌方 `lane_order`、前后排、卡位编号排序。
- `all_enemies_same_lane` 在非对称棋盘上指当前路所在路线分组的对方全部物理路；它可能覆盖多个敌方物理路。需要只覆盖单一物理路的效果必须使用明确的单路目标选择器。
- `all_friendly_same_lane` 仍指施法者所在的己方物理路，不扩展为同路线分组的所有友方路。跨己方多路的效果必须使用 `all_friendly_same_route` 或 `all_allies`。
- 每路只属于一个路线分组，第一版不支持路中途分叉、动态改道或一条物理路同时属于多个分组。

### 2.5 部署位置

- 一个卡位同一时间最多容纳一个干员或召唤物；召唤物是否占据卡位由其 token 数据显式配置。
- `deploy_rule` 支持 `front_only`、`front_or_back`、`back_only`。若没有配置，沿用攻击类型默认值：近战 `front_only`；远程 `front_or_back`。
- 原生浮空干员或 token 默认只能部署后排；卡牌明确允许时可覆盖，但不得部署到不存在的后排卡位。
- 远程单位可以部署后排，也可以按 `deploy_rule` 部署前排。前排/后排均是相对控制者的本方位置。
- 如果合法位置已满、目标卡位不存在、费用不足或 CD 未归零，部署失败且不得发生部分状态变更。
- `owner_id`、`controller_id`、`board_half` 继续分开记录；本版不实现夺取控制权。
- 当前普通攻击类型仍为 `melee` 与 `ranged`。将来增加 `special` 时，必须提供独立普通攻击目标算法；没有目标算法的 `special` 单位不得自动攻击。

### 2.6 标准排序键

所有需要遍历卡位的规则统一使用以下稳定顺序：

1. `lane_order` 从小到大；
2. `row_order`：`front` 在 `back` 之前；
3. `slot_index` 从小到大；
4. 若仍相同，使用稳定的 `card_instance_id` 字典序作为最后兜底。

不得依赖 JSON 数组偶然顺序、对象键顺序、组件渲染顺序或单位进入战场的时间来决定攻击/目标优先级。

## 3. 牌组与开局

- 标准构筑目标为每套 30 张，同名卡最多 2 张。
- Demo 或测试牌组可以使用较小固定牌组验证系统，但这只是测试卡池/牌组配置，不改变任何卡牌、回合、撤离、战斗或状态规则。
- 首发完整卡池规划为 144 种不同卡牌：72 张干员、48 张战术、24 张支援。卡牌稀有度用于收藏和抽卡，不自动增加战斗属性。
- 双方选择牌组并洗牌，基本分设为 20，费用设为 0。
- 双方各抽 5 张起手牌。
- 双方各进行一次起手换牌：选择 0–5 张放入暂存区，从牌库抽取相同数量的新牌，再将暂存卡洗回牌库。起手换牌不触发疲劳；双方均完成后随机决定先手。
- 随机决定先手后，回合严格交替：A→B→A→B，不会出现同一玩家连续获得完整行动回合。

## 4. 费用、抽牌与疲劳

### 4.1 费用

- 当前玩家每个己方回合开始获得 3 点费用，费用上限为 10。
- 未使用费用保留；获得费用超过上限的部分舍弃。
- 部署、战术、支援和装备按各自 `cost` 支付；效果可以减免或增加费用，但最终费用不能低于 0。
- 每次成功部署必须记录实际支付费用，含折扣后的真实数值。
- 所有动作必须先校验阶段、目标、位置、状态、CD 和费用，再原子提交。非法动作不得部分扣费、移牌或触发效果，并应向玩家显示原因。

### 4.2 抽牌与疲劳

- 每名玩家在自己回合开始时抽 1 张牌。
- 手牌上限建议为 10。手牌已满时，若牌库仍有牌，抽到的牌进入弃牌堆；这不算抽牌失败，也不产生疲劳。
- 每当规则要求抽牌而牌库为空，产生一次疲劳：该玩家第一次失败抽牌造成 1 点基本分伤害，第二次 2 点，第三次 3 点，依此递增。双方疲劳计数独立且不重置。
- 抽多张牌时逐张处理，每次空抽分别增加疲劳伤害。
- 疲劳伤害不受干员护盾和普通减伤影响，除非卡牌明确写明。
- 弃牌堆默认不自动洗回牌库；洗回效果不会重置疲劳计数。
- 撤离返回手牌不受手牌上限限制，不会因此丢弃。

## 5. 回合结构

每名玩家回合固定四阶段：`turn_start → action → combat → turn_end`。

### 5.1 回合开始 `turn_start`

执行顺序：
1. 重置己方每回合限次标记（不包含再部署次数计数；本规则没有全局再部署次数上限）。
2. 获得 3 点费用（不超过上限）。
3. 抽 1 张牌；空抽则按疲劳规则结算。
4. 结算 `turn_start` 触发效果。
5. 己方场上每名未冰冻干员按 `sp_regen_per_turn` 回复 SP，默认 +1；冰冻干员不获得 SP。
6. 检查胜负，未结束则进入行动阶段。

回合开始时的 SP 回复只作用于当时已在场的干员；在本回合行动阶段新部署的干员不会追溯获得本次自然回复。冻结期间所有来源的 SP 增加均被阻止，详见第 10 节。

### 5.2 行动阶段 `action`

玩家可按任意顺序、重复执行合法操作，直到主动结束行动阶段：

- 首次部署或再部署干员；
- 使用战术卡；
- 打出支援设施或装备；
- 发动己方干员主动技能；
- 普通撤离；
- 使用快速撤离或其他强制撤离效果。

本规则不限制行动阶段的撤离/再部署次数。相同干员能否重新进入战场只由该卡实例的 `redeploy_cd_remaining`、费用、部署位置与效果限制决定。多个不同干员可在同一行动阶段内依次调度；同一干员也可在 CD 为 0 时于同一行动阶段再次部署。

玩家可在部署、战术、技能和撤离操作之间自由交替。结束行动阶段后不能再主动执行这些操作，除非卡牌明确规定在战斗阶段或其他阶段使用。

本回合行动阶段任何时候进入战场的干员，默认不能参加本回合普通攻击；但若其 SP 足够，可以在行动阶段发动主动技能。其被动和反应技能按各自状态和触发规则处理。程序需记录 `entered_battle_this_owner_turn`：本回合首次部署/再部署时设为 true，撤离重置不得清除；在该玩家下一个回合开始时重置为 false。这样同一回合内快速撤离、反复再部署不会获得额外普通攻击。

**不设置行动阶段现实时间限制，也不设置玩家级再部署次数上限。** 自动触发链另有程序安全阀，不能把安全阀当作玩家操作次数限制。

### 5.3 战斗阶段 `combat`

- 只有当前回合玩家控制的干员进行普通攻击；对手干员不会因此进行普通攻击。
- 对手干员仍可触发符合状态限制的被动、反应和防御效果。
- 每名符合条件的己方干员每个己方战斗阶段默认进行一次普通攻击；追加攻击必须由卡牌明确规定。
- 攻击者按本方棋盘 `lane_order` 从小到大、每路前排先于后排、同排 `slot_index` 从小到大依次行动。
- 每个符合条件的卡实例每个己方战斗阶段默认只攻击一次；一条路连接多个敌方物理路也不会增加攻击次数。
- 每次攻击后立即结算伤害、护盾、阵亡、SP 和触发效果；下一名攻击者重新选择目标。

### 5.4 回合结束 `turn_end`

1. 结算己方 `turn_end` 效果。
2. 更新持续状态与持续效果时间。
3. 对该玩家拥有的、在本次撤离后需要跳过己方行动阶段的卡实例，按 CD 规则递减冷却。
4. 检查双方基本分；未结束则切换玩家。

持续时间按状态定义的拥有者回合计算。一个状态若在目标本次回合中途施加，不会在同一回合结束时被错误地提前扣除完整持续时间。

## 6. 普通撤离、快速撤离与强制撤离

### 6.1 普通撤离的合法条件

普通撤离是行动阶段的基础操作，不消耗手牌。目标必须同时满足：

1. 是当前玩家控制的己方干员；
2. 当前位于当前控制者自己的半区，即 `board_half == controller_id`；
3. 当前没有任何 `blocks_normal_withdrawal=true` 的状态；本规则初始将 `stun`、`freeze` 配置为禁止普通撤离；
4. 当前在战场上。

因此，处于眩晕或冰冻状态、或被位移到对方半区的己方干员，均不能被普通撤离。`slow`、`grounded`、`taunt` 默认不禁止普通撤离。未来新增控制状态必须明确配置是否阻止普通撤离，不能仅凭名称推断。

普通撤离次数没有上限，但每次撤离都会给该卡实例设置再部署 CD。玩家可以连续撤离不同干员；同一干员只有在 CD 归零后才能再次部署。

### 6.2 普通撤离退款

统一公式：

`refund = floor(current_deployment_paid_cost × effective_refund_ratio)`

其中 `effective_refund_ratio = card.normal_withdrawal_refund_ratio`；若卡牌未配置该字段，则使用费用档位默认值：cost 1–2 = 0.50，3–4 = 1/3，5–6 = 0.25，7+ = 0.20。

- `normal_withdrawal_refund_ratio` 是卡牌数据参数，建议合法区间为 0.20–0.50；未设置时采用上述费用档位默认值。测试卡可统一配置 0.50，完整卡池可按费用、职业和角色强度覆写，但不改变公式。
- 退款基于最近一次实际支付费用，而非印刷 `cost`。
- 免费部署的实际支付费用为 0，撤离退款为 0。
- 退款受玩家费用上限影响，超额部分舍弃。
- 退款先读取并结算，随后清除本次部署的支付记录，避免同一次部署被重复退款。

### 6.3 快速撤离 `rapid_withdrawal`

- 快速撤离是一张 `cost=0` 的战术卡，在行动阶段打出并消耗该手牌。
- 成功时，将目标己方干员返回手牌，返还其最近一次部署的全部实际支付费用，并将本次撤离产生的 `redeploy_cd_remaining` 减少 1，最低为 0。
- 快速撤离明确属于战术强制撤离，因此允许撤离处于 `stun`、`freeze` 等禁止普通撤离状态的己方干员。
- **本版建议：快速撤离同时允许回收位于对方半区的己方干员**，因为半区限制只约束普通撤离；目标仍必须由当前玩家控制，不能选择敌方控制的单位。此设定应作为快速撤离卡牌文本的一部分，而不是所有战术卡自动拥有的能力。
- 快速撤离消耗一张手牌，即使其费用为 0，也有手牌机会成本。
- CD 降为 0 后，只要当前仍处于行动阶段且其他部署条件满足，该干员可以立即重新部署；重新部署仍支付新一次部署费用并重新触发 `on_deploy`。

### 6.4 其他效果型/战术型强制撤离

- 任何战术卡或技能效果都可以在其文本和数据中定义返回手牌/强制撤离。
- 普通撤离限制不会自动套用到强制撤离；但强制撤离也不会自动绕过全部限制。每个效果必须明确配置 `ignore_control_restriction`、`ignore_half_restriction`。
- 未明确豁免时，强制撤离默认仍不能移除被控制或位于对方半区的单位；快速撤离作为本规则中特别定义的卡牌，明确豁免这两项。
- 效果型强制撤离的退款策略必须明确写为 `none`、`normal_ratio`、`full_paid_cost` 或固定数值；默认 `none`。
- 效果型强制撤离的 CD 默认使用该干员的 `redeploy_cd_base`；卡牌可明确增减 CD。
- 强制撤离不会触发死亡、友方阵亡或击杀；会触发 `on_leave_field`。

### 6.5 撤离后的战斗状态重置

普通撤离、快速撤离以及明确写明“返回手牌并重置”的强制撤离，成功后将干员战斗状态恢复到当前卡牌定义的初始状态：

- `current_hp = hp`；
- `current_atk` 及其他可计算战斗属性恢复为卡牌基础值；
- `current_sp = starting_sp`；
- 护盾归零；
- 清除所有临时增益、减益、眩晕、冰冻、减速、临时落地、临时嘲讽及其他战斗状态；
- 附着装备解除，装备卡进入拥有者弃牌堆；装备产生的数值修正随之移除；
- 原生卡牌词条（例如原生 `floating`、基础嘲讽）保留；
- 卡实例身份、所有者/控制者、`has_deployed_before`、生命周期标记、`entered_battle_this_owner_turn` 及 `redeploy_cd_remaining` 保留；
- 退款在重置前读取 `current_deployment_paid_cost`；处理完毕后清除该次支付快照。再次部署时写入新的实际支付费用。

撤离不算阵亡；不会触发 `on_death`、`on_ally_death` 或 `on_kill`。撤离也不会清除再部署 CD 或一次性/整局使用标记，除非卡牌明确写明重置。

### 6.6 CD 的设置与计时

- 每张干员卡定义 `redeploy_cd_base`，表示普通撤离后需要跳过的后续己方行动阶段数；普通撤离最低为 1。
- CD 属于卡实例生命周期元数据，不因战斗状态重置而清零。
- 每次正常撤离或未特别修改 CD 的强制撤离，将 `redeploy_cd_remaining` 设为该卡的 `redeploy_cd_base`。
- 快速撤离将这次 CD 减少 1，最低为 0。
- CD=0 时，只要当前仍处于行动阶段且其他条件满足，就可以重新部署；CD>0 时不能部署。
- 撤离发生的当前行动阶段不计入 CD。每经过一个后续的己方行动阶段，在该行动阶段结束时减少 1；当 CD 归零后，从之后的可执行动作时机起允许部署。
- 实现时必须记录 `redeploy_cd_applied_owner_turn_index`（设置 CD 时的卡牌控制者回合序号），只允许在序号更大的后续己方回合结束时递减，避免撤离当回合结束时错误扣除 CD。
- 不使用现实时间、对手回合或双方完整轮次计时。
- 全局再部署次数没有上限，不存在 `redeploys_used_this_turn` 或同义玩家级计数器。

**卡牌 CD 配置建议（用于生成卡牌初始数值，不是第二套模式规则）：**

| 印刷 cost | 建议基础 CD |
|---:|---:|
| 1–2 | 1 |
| 3–4 | 2 |
| 5–6 | 3 |
| 7+ | 4 |

职业修正候选：先锋 -1、特种 -1、重装 +1，其余职业 0；最终值建议限制在 1–5，并允许卡牌级覆盖。此表需与退款比例、部署触发收益共同进行模拟调整。当前测试卡只是在同一字段中填写较简单的数值，不拥有不同的规则逻辑。

## 7. 部署触发与重复收益

- 每次干员成功从手牌进入战场（首次部署或再部署）均触发一次 `on_deploy`。
- 不设置默认的每实例每回合部署触发上限，也不限制玩家回合内的部署/撤离操作次数。
- 每次成功部署事件内，同一触发器默认执行一次；只有卡牌明确声明多段触发才执行多次。
- 位置非法、费用不足、CD 未归零、目标非法时部署失败：不扣费、不移牌、不改变实例状态、不触发 `on_deploy`。
- 部署触发获得费用、SP、造成伤害、治疗、召唤等效果均可重复触发；这属于游戏的调度构筑机制。
- 每个根事件自动触发链设置最大深度 32，防止程序递归故障。该安全阀不限制玩家主动操作数量，也不能代替卡牌平衡。
- 卡牌审查必须计算循环净费用：`net_cost_per_cycle = redeploy_paid_cost - withdrawal_refund - on_deploy_cost_gain`。若净费用 ≤0，且重复部署能继续造成伤害、抽牌、治疗、护盾或其他可累计收益，则属于高风险循环，必须通过卡牌 CD、退款比例、部署费用或效果强度调整，而不是默认禁止重复部署触发。
- `once_per_turn`、`once_per_game` 等限制只在卡牌明确声明时使用，撤离重置不得自动清除这些生命周期标记。

## 8. 技力 SP 与技能

### 8.1 SP 资源

- 每名干员独立拥有 `current_sp`、`max_sp`、`starting_sp`。
- 默认 `max_sp=5`、`starting_sp=0`；每名干员可以单独配置。
- 默认每个己方回合开始自然回复 +1 SP；特殊干员可以将 `sp_regen_per_turn` 设为 0，改由受击、受伤、击杀或其他效果获得 SP。
- `sp_gain_on_attacked`：成为一次有效攻击目标后获得 SP；即使护盾完全吸收，只要攻击确实命中目标，仍属于受击。
- `sp_gain_on_damaged`：实际 HP 减少后获得 SP；护盾完全吸收不触发。
- `sp_gain_on_kill`：某干员作为可识别来源使敌方干员阵亡后获得 SP，默认建议 +1；范围效果/单个根攻击事件的击杀奖励总量可由卡牌/规则参数设置上限，建议初始为 2。
- 战术卡或支援效果直接增加 SP，使用统一 `gain_sp` 入口。
- SP 不能低于 0 或超过 `max_sp`；溢出部分舍弃。手牌、牌库和弃牌堆中的干员不获得 SP。

### 8.2 冰冻期间 SP 封锁

- 冰冻期间任何来源的 SP 增加全部失效：自然回复、受击、受伤、击杀、友方辅助、支援、装备、战术卡和其他技能效果均不能增加 SP。
- 被封锁的 SP 不排队、不延迟、不在解冻后补发；已有 SP 保留。
- 眩晕不封锁 SP 获取。

### 8.3 技能类型

- 主动技能 `active`：当前玩家在行动阶段主动发动，消耗 `sp_cost`；被冻结或眩晕的干员不能发动。
- 条件被动 `passive_free`：满足条件自动生效，不消耗 SP。
- 技力被动 `passive_sp`：满足事件条件时，若 SP 足够则先扣 SP 再发动；不足则本次不发动、不排队。
- 反应技能 `reaction_sp`：受到攻击、实际受伤、友方阵亡等事件触发，可在非拥有者回合自动发动；按状态和 SP 条件判断。
- 主动、技力被动、技力反应共用同一干员 SP 池。
- 同一事件触发多项自动技力技能时，按 `skill_priority` 从高到低检查；同优先级按稳定卡实例顺序。
- 受击反应在伤害结算前检查和支付 SP；本次攻击产生的受击/受伤 SP 回复在攻击伤害与相关死亡结算之后处理，不能反过来支付同一次攻击的前置反应技能。

## 9. 自动战斗、行动顺序与目标选择

### 9.1 攻击者队列

- 只有当前回合玩家控制的干员进行普通攻击；对手干员不会因此进行普通攻击。
- 对手干员仍可触发符合其状态限制的被动、反应和防御效果。
- 每名符合条件的己方干员每个己方战斗阶段默认进行一次普通攻击；追加攻击必须由卡牌明确规定。
- 攻击队列按本方 `lane_order` 从小到大；同一路先前排、再后排；同一排按 `slot_index` 从小到大。
- 同一物理卡位上最多一个单位。队列在战斗阶段开始时生成卡实例 ID 快照；轮到单位时重新检查其是否仍在场、存活、未被控制、不是本回合新部署且未攻击。
- 战斗阶段中新召唤的单位默认不加入本次普通攻击队列；卡牌明确规定时例外。

### 9.2 拦截资格

`intercept_eligible` 是运行时派生值，不作为可随意改写的基础属性。单位必须同时满足：在场、存活、当前为地面状态、未眩晕、未冰冻，并且占据有效卡位。前排和后排地面单位都可能具有拦截资格；前排所有合法目标均失去资格后，后排地面单位可以成为目标。

原生浮空效果生效时：
- 浮空单位不拦截基本分攻击；
- 近战普通攻击不能选中浮空单位；
- 远程普通攻击在同路线分组内没有可拦截地面目标时，优先选择合法浮空单位，再考虑攻击基本分。

当浮空关键词被沉默/冰冻等明确抑制时，单位按其实际卡位上的普通地面单位处理；若在后排，则是后排地面单位。沉默结束后自动恢复卡牌定义的浮空效果（除非仍有独立 `grounded` 状态）。

### 9.3 普通攻击的默认目标优先级

每次普通攻击开始时重新选择目标。候选目标仅来自攻击者所在 `route_group_id` 对方的物理路，且必须满足攻击类型、距离/范围和状态合法性。

目标类别优先级：

1. 合法嘲讽目标；
2. 有拦截资格的地面前排单位；
3. 有拦截资格的地面后排单位；
4. 若攻击者为远程，合法浮空单位；
5. 没有合法干员目标时，攻击敌方基本分。

同一类别内的稳定排序：目标方 `lane_order` → 前排优先于后排 → `slot_index` 从小到大 → `card_instance_id`。因此，同一路多个前排单位中优先攻击 1 号卡位；多个嘲讽单位也按同一稳定排序，前排 1 号嘲讽最先被选中。

补充：
- 嘲讽只提高本来合法目标的普通攻击优先级，不能让攻击者攻击其攻击类型无法攻击的目标；近战不能因嘲讽而攻击正在生效的浮空单位。
- 沉默会压制标记可沉默的嘲讽效果；该单位仍按其所在卡位作为普通单位参与目标排序。
- 眩晕/冰冻单位失去拦截资格，且不作为默认普通攻击目标。
- 若地面拦截单位不存在但存在浮空单位，近战攻击者不能攻击浮空单位，直接攻击基本分；远程攻击者优先攻击浮空单位。
- 若一组有多个敌方物理路，按以上“目标类别优先、敌方路序其次”的规则在整个路线分组中查找，而不是让一个攻击者重复攻击每一条路。
- 卡牌可通过 `target_scope`、`target_priority`、`can_target_floating`、`ignore_taunt`、`ignore_front_interception` 覆盖默认规则，但必须保持目标合法性约束。

### 9.4 单次普通攻击时序

1. 检查攻击者是否仍可攻击。
2. 按 9.3 选择目标；没有合法干员目标时选择敌方基本分。
3. 建立攻击事件并触发 `on_attack_declared`；计算攻击方增伤、光环和其他攻击前修正。
4. 若目标是干员，检查其合法 `on_attacked` 反应；按技能优先级先支付 SP，再发动防御效果。
5. 应用攻击力、增伤、减伤；伤害最低为 0。护盾先吸收伤害，剩余伤害扣除 HP；攻击基本分时扣除 `base_points`。
6. 处理 `on_damaged`、濒死/防止阵亡、阵亡、击杀和对应 SP 获取。
7. 主攻击的伤害与伤亡结算完成后触发 `on_attack_resolved`；处理溅射、追加状态等后续效果。
8. 当前攻击及其必要触发链完成后，才轮到下一名攻击者；下一名攻击者重新选择目标。

攻击一旦完成目标选择并进入攻击事件，即视为已提交。目标反应可以减伤、加护盾、反伤或改变后续状态；除非效果明确带有 `cancel_attack`，否则不能追溯取消已经提交的攻击。若目标在伤害结算前因反应离场，本次攻击结束，不自动改打其他单位。

过量伤害默认不溢出。目标剩余 2 HP、受到 6 点单体伤害时，该目标阵亡，超出的 4 点消失；下一次独立攻击重新选择目标。穿透、溢出、多目标和多段攻击必须在卡牌中明确。

### 9.5 范围攻击：范围、筛选与目标数量分离

技能/战术效果必须分别定义：

- `target_scope`：从哪里选目标；
- `target_filter`：哪些单位符合资格；
- `target_count`：最多选择几个，或 `all`；
- `target_priority`：超过目标数量时如何排序；
- `respect_taunt`：是否服从普通攻击嘲讽规则，默认为 `false`。嘲讽默认只影响普通攻击。

第一版标准范围选择器：

| 选择器 | 目标集合 |
|---|---|
| `single_enemy_same_lane` | 当前路所属路线分组中的一个敌方单位 |
| `all_enemies_same_lane` | 当前路所属路线分组中所有合法敌方单位 |
| `all_enemies_front_same_lane` | 当前路线分组所有敌方前排单位 |
| `all_enemies_route_group` | 与 `all_enemies_same_lane` 同义的显式命名，建议新卡使用此名称 |
| `primary_enemy_lane` | 当前路线分组中按目标方 `lane_order` 最小的物理路 |
| `all_enemies_primary_lane` | 仅主目标物理路内的所有合法敌人 |
| `all_friendly_same_lane` | 施法者所在己方物理路的全部合法友方单位 |
| `all_friendly_same_route` | 当前己方路线分组中所有己方物理路的合法单位 |
| `all_allies` / `all_enemies` | 全场己方/敌方单位 |
| `single_ally` | 一个符合条件的己方单位 |
| `self` | 效果来源自身 |

`adjacent_lanes` 等依赖几何距离或相邻拓扑的选择器暂不纳入第一版可执行范围；若未来引入，必须在 BoardProfile 中提供明确邻接关系，不能按字符串路名推断。

### 9.6 AOE 目标快照与结算

1. 技能合法性确认后，根据目标范围、筛选、数量和排序建立目标 `card_instance_id` 快照。
2. 按敌方/己方 `lane_order`、前后排、卡位编号稳定排序；若 `target_priority` 指定最低 HP 比例等策略，则先按该策略排序，再用稳定卡位顺序打破平局。
3. 快照生成后不新增后来进入范围的单位，也不因为前一个目标阵亡而临时补选替代目标。
4. 轮到快照中的目标时，若其已阵亡或离场则跳过；若仍在场，则按当前合法性与效果描述结算。目标移动不会把新单位加入快照。
5. 每个目标的伤害、护盾、状态、阵亡和事件立即结算，再处理快照中的下一个目标。

### 9.7 治疗、护盾与辅助目标

- 单体治疗默认仅选择 `current_hp < hp` 的存活友方单位；默认优先 `lowest_hp_ratio`（当前 HP / 最大 HP 最低）。
- 若技能动作使用 `chosen_friendly` / `chosen_enemy_same_lane` 等 `chosen_*` 目标，真人玩家可在合法目标中手动选择；机器人按卡牌 `target_priority` 选择，治疗默认 `lowest_hp_ratio`。未声明 `chosen_*` 的自动触发效果由引擎按 `target_priority` 自动选取。
- HP 比例相同时，按己方 `lane_order`、前排、`slot_index`、`card_instance_id` 排序。
- 护盾、增益等单体辅助必须声明目标筛选和优先级；未写明时使用存活目标的稳定卡位顺序，不得随机选择。
- 群体治疗/群体辅助对范围内全部符合筛选条件的单位生效。
- 若主动技能或 SP 被动没有合法目标，不支付 SP、不进入冷却、不触发后续动作；主动技能按钮应显示无法发动的原因。
- 目标优先级由规则引擎统一实现，卡牌数据只声明范围、筛选、数量和策略，不为每张卡编写独立选目标代码。

## 10. 状态效果

### 10.1 眩晕 `stun`

- 禁止普通攻击和主动技能；失去拦截资格；禁止普通撤离。
- 不封锁 SP 获取。
- 默认允许条件被动和满足条件的反应技能触发，除非技能另有限制。
- 原生浮空在眩晕期间暂时失效；眩晕结束后，若没有独立 `grounded` 状态则恢复浮空。
- 默认持续至目标下一次己方回合结束；具体卡牌可以配置持续时间。

### 10.2 冰冻 `freeze`

- 禁止普通攻击、主动技能、事件型被动和反应技能；持续被动属性/光环默认仍存在，除非对应永续效果显式配置 `suppressed_by` 包含 `freeze`。
- 失去拦截资格；嘲讽和浮空关键词按本规则默认被冰冻压制；禁止普通撤离。
- 封锁所有来源的 SP 获取；已有 SP 不清零。
- 原生浮空在冰冻期间暂时失效；冰冻结束后，若没有独立 `grounded` 状态且没有其他压制来源，则恢复浮空。
- 普通伤害不会自动解除冰冻，除非卡牌明确规定。
- 默认持续至目标下一次己方回合结束；具体卡牌可以配置。
### 10.3 临时落地 `grounded`

- 只作用于原生具有 `floating=true` 的后位干员。
- 普通位移造成的临时落地默认持续 2 个目标所属玩家的己方回合；持续时间是可配置数值，未来通过平衡调整。
- 落地期间按后位地面干员处理，可被近战普通攻击选中；若未眩晕/冰冻则具有后位拦截资格。
- 眩晕/冰冻对浮空的暂时压制与 `grounded` 独立计时；控制结束后，如果 `grounded` 仍存在，继续按地面单位处理。
- 本规则版本不实现永久移除浮空、强力位移或精英化位移。
- 落地计时按目标拥有者自己的回合计算；状态施加所在回合不扣完整一回合，之后每结束一个目标己方回合减 1。

### 10.4 减速 `slow`

默认使目标下一次己方战斗阶段普通攻击力 -1，最低为 0。除非卡牌明确说明，不禁止主动技能、被动/反应、SP 获取、拦截或普通撤离。

### 10.5 护盾 `shield`

护盾先吸收 HP 伤害。被攻击但护盾完全吸收仍触发 `on_attacked` 和受击 SP 回复；不触发 `on_damaged` 和受伤 SP 回复。护盾持续时间按卡牌文本；未写明时保留至消耗或宿主离场。

### 10.6 状态叠加与冲突

- `freeze` 与 `stun` 同时施加时，控制效果不叠加成更高等级；保留剩余时间更长的冰冻，眩晕不额外延长冰冻。
- 同类状态再次施加，默认刷新为较长剩余时间，不叠加数值，除非卡牌明确允许。
- `grounded` 与 `stun`/`freeze` 独立计时；控制结束后若落地仍在，则继续落地。
- 持续被动属性和静态光环不会仅因冰冻而移除；冻结封锁的是事件型被动/反应和 SP 增加。

---

### 10.7 沉默 `silence`

沉默是技能压制状态，不是 SP 封锁状态。默认持续至目标下一个己方回合结束；持续时间由施加状态时记录目标的拥有者回合序号确定，施加所在回合不提前消耗完整持续时间。

沉默期间：

- 目标不能发动主动技能；目标拥有的 `passive_free`、`passive_sp`、`reaction_sp`、`on_deploy`、攻击触发、事件型技能和 `continuous` 技能效果均不生效。
- 目标仍可正常普通攻击（前提是没有 stun/freeze 等其他禁止攻击的状态）。
- 所有 SP 获取正常结算：自然回复、受击、受伤、击杀、外部效果直接授予 SP 均可获得；仍受 `max_sp` 上限约束。
- 不清空已有 SP，不延迟或排队技能触发，不自动移除已经结算的减速、眩晕、护盾、治疗等状态。
- 目标提供的可沉默永续效果（例如嘲讽、浮空、被动光环）暂时失效；这些效果由其来源卡牌恢复后自动重新生效，无须重新施加。
- 不抑制其他单位施加给该目标的效果；沉默只压制沉默目标自身提供/拥有的技能和永续效果。
- 不改变基础 ATK、HP、Cost、攻击类型、部署限制等非技能固有属性。

强度关系：冰冻比沉默更强，除技能压制外还封锁全部 SP 获取、禁止普通攻击、失去拦截资格，并压制嘲讽/浮空；眩晕禁止普通攻击/主动技能并失去拦截资格，但不封锁 SP，也不默认压制全部被动光环。

### 10.8 永续效果与压制 `persistent_effects_json`

卡牌数据可以定义 `persistent_effects_json`，用于表达持续提供的关键词、被动光环、持续属性修正或规则修正。每个效果至少包含：`effect_id`、`effect_type`、`duration`、`suppressed_by` 和必要的参数。

- 默认由技能/被动提供的永续效果可被 `silence` 压制；例外必须在数据中明确声明。
- 嘲讽和浮空作为永续关键词效果，默认 `suppressed_by: ["silence", "freeze"]`。
- 静态基础属性（基础 ATK/HP、攻击类型、固有部署限制）不属于可沉默永续效果，不写入该数组。
- 冰冻只压制明确标记包含 `freeze` 的永续效果；按 v0.7 延续规则，普通持续光环默认不因冰冻消失，但可被沉默压制。
- `effective_keywords`、`intercept_eligible`、有效光环与有效属性必须在计算时根据当前状态动态派生；不得因沉默把卡牌源数据中的 `taunt`/`floating` 永久改成 `false`。
- 沉默/冰冻结束后重新计算有效效果；若效果仍在持续时间内则恢复，不重新触发 `on_deploy` 或其他一次性事件。
- 对已经落地的浮空单位，`grounded` 是独立计时状态。沉默/冰冻取消后，若 grounded 仍存在，则继续按地面单位处理；grounded 结束且没有其他压制时再恢复浮空。

建议数据示例：

```json
{
  "persistent_effects_json": [
    {
      "effect_id": "bubble_taunt",
      "effect_type": "keyword",
      "keyword": "taunt",
      "scope": "same_lane",
      "duration": "permanent",
      "suppressed_by": ["silence", "freeze"]
    }
  ]
}
```

`taunt_scope`、`floating` 等旧字段在迁移期可作为兼容输入，但导入器应将其转换为统一的永续效果对象；完成迁移后，运行时只认一个规范化结果，禁止同一效果重复读取。

## 11. 支援、装备与卡实例生命周期

- 支援卡分设施 `facility` 和装备 `equipment`，都在行动阶段打出。
- 每方最多同时存在 2 个持续设施；每名干员默认最多附着 1 件装备，除非卡牌提高装备位。
- 撤离/阵亡时装备解除并进入拥有者弃牌堆；设施不因某名干员撤离而自动离场。
- 每张实体卡副本有独立 `card_instance_id`；同名副本的 HP、SP、CD、状态、部署历史和支付费用不共享。
- 撤离重置战斗状态，但不重置卡实例身份、`owner_id`、`controller_id`、`has_deployed_before`、`entered_battle_this_owner_turn`、生命周期标记、`redeploy_cd_remaining`。
- 任何“一次/每局”标记默认属于卡实例生命周期，不因普通撤离重置；只有卡牌明确说明才重置。

## 12. 效果事件、技能 DSL 与程序安全

### 12.1 标准事件名

标准事件包括：`turn_start`、`turn_end`、`on_play`、`on_deploy`、`on_attacked`、`on_damaged`、`on_damage_survive`、`on_lethal`、`on_death`、`on_ally_death`、`on_kill`、`on_heal`、`on_leave_field`、`on_attack_declared`、`on_attack_resolved`、`on_friendly_attack_declared`、`combat_end`。

- `on_attacked`：成为一次已提交攻击的目标；护盾完全吸收仍触发。
- `on_damaged`：HP 实际减少；护盾完全吸收不触发。
- `on_attack_declared`：攻击者和目标已确定、伤害尚未结算；用于攻击前增伤/修正。
- `on_friendly_attack_declared`：己方其他单位的攻击已声明；用于铃兰等友方攻击协同效果。
- `on_attack_resolved`：主攻击的伤害、濒死、阵亡和击杀结算完成；用于主攻击后的溅射/追加状态。
- `on_leave_field` 与 `on_death` 必须分开；撤离不会被误判为阵亡。
- `continuous` 不是事件名，不进入事件队列；它是在属性、攻击、目标合法性或光环查询时动态检查的持续条件。

### 12.2 事件执行顺序

普通攻击顺序按第 9.4 节。每个事件触发器按照 `skill_priority` 从高到低执行，同优先级按稳定卡实例顺序。受击反应先支付 SP，再结算本次攻击产生的 SP 回复。事件链中的状态变化立即可被后续事件读取，除非该效果明确要求原子快照。

### 12.3 技能效果 DSL

- 卡牌效果 JSON 只能使用白名单动作、条件、目标选择器和持续时间类型；禁止执行任意 JavaScript、动态表达式或任意函数名。v1.1 当前已用动作至少包括 `apply_status`、`bonus_damage`、`buff_attack`、`damage`、`debuff_attack`、`gain_cost`、`gain_sp`、`heal`、`if_else`、`move`、`prevent_lethal`、`reduce_damage`、`shield`、`summon`；实现前仍须从 JSON 递归扫描全部分支，确认完整白名单。
- `if_else` 分支在动作开始时获取一次状态快照，按声明顺序判断条件，只执行第一个满足条件的分支。单个分支内的动作按声明顺序原子执行；不得在执行第一个动作后重新评估后续分支条件。
- `moved_target` 必须引用导致该位移的同一 `card_instance_id`，不得因位置变化重新选择目标。
- `target_is_floating`、`enemy_front_exists`、`back_slot_empty` 等条件必须读取动态有效状态与当前 BoardProfile，不能读取 UI 显示文本。
- `active_skill_used_this_owner_turn` 是卡实例/回合追踪标记，用于执行本回合主动技能后续代价；撤离重置不得意外清除。
- 每个动作必须定义触发时机、目标范围、目标筛选、SP 费用（如有）、持续时间、叠加方式、次数限制、失败行为和状态免疫检查。

### 12.4 程序安全

自动效果使用事件队列；单根事件触发深度设置 32 作为防递归安全阀，超出时记录错误并中止异常链。此安全阀不限制玩家主动部署、撤离、再部署或卡牌的合法触发次数。规则引擎必须提供可解释日志，包括事件名、来源卡实例、目标实例、SP 支付/获取、状态压制原因和动作失败原因。

## 13. 胜负判定与模式

### 13.1 标准对战 `duel`

- 任一方 `base_points <= 0`，当前不可分割效果及必要触发链完成后判定胜负。
- 一方基本分归零，另一方获胜；同一不可分割效果同时令双方基本分归零，判为平局。
- 标准对战默认不设置固定回合上限；疲劳推动自然终局。
- 对局结束后不再执行后续攻击、动作或回合。

### 13.2 攻防模式 `siege`

攻防模式允许双方独立设置路数、前后排卡位、基地 HP 和路线分组。双方身份分别指定为 `attacker` 与 `defender`。

- 双方基地 HP 分别取 BoardProfile 中配置值；没有特殊配置时不强制相等。
- `round_limit` 表示完整轮次数：每个完整轮次包含攻方和守方各完成一个完整玩家回合；不是总共只有 N 次玩家回合。
- 任一方基地在回合上限之前降至 0，按标准规则立即判定胜负；同一不可分割效果同时击破双方则平局。
- 达到 `round_limit` 且守方基地仍大于 0 时，守方获胜；攻方的目标是在限定轮次内击破守方基地。
- 第一版不加入平局判定、积分裁定或剩余 HP 比较；若未来需要赛事积分规则，应作为独立胜负配置扩展。

### 13.3 模式隔离原则

`duel` 与 `siege` 共享部署、攻击、费用、撤离、SP、技能、状态和效果引擎。差别只由棋盘布局、玩家角色、基地 HP、轮次上限和胜利策略配置决定；不得复制一套攻防专用战斗引擎。

---

### 13.4 v1.1 干员卡池兼容性说明

当前 `arknights_operator_pool_v1.1` 使用了以下 v0.8 才正式补齐的扩展：`persistent_effects_json` 的迁移目标、`on_attack_declared`、`on_attack_resolved`、`on_friendly_attack_declared`、`continuous`、`if_else`、`moved_target`、`target_is_floating`、`enemy_front_exists`、`back_slot_empty`、`active_skill_used_this_owner_turn` 及多种范围目标选择器。卡池旧字段 `taunt_scope`/`floating` 暂时仍需通过导入适配器处理。

因此 v1.1 不能被描述为已经完全兼容 v0.7 引擎，也不能仅因为 JSON 能解析就视为玩法已实现。导入器必须验证字段/事件/动作白名单；引擎必须逐项实现并通过规则测试；之后仍需机器人对局验证数值平衡。

## 14. 统一规则与数据配置原则

Demo、内部测试和正式版本使用同一套规则逻辑。以下差别只能通过配置数据体现，不得写成互斥规则分支：

- 牌组张数、卡池规模与卡牌数量；
- 每张卡的 `cost`、`normal_withdrawal_refund_ratio`、`redeploy_cd_base`；
- 干员的 HP、ATK、SP 上限、起始 SP、SP 回复和技能消耗；
- 技能效果、状态持续时间、目标优先级和永续效果压制配置；
- `BoardProfile`（棋盘布局、路线分组、基地 HP、模式与胜负参数）；
- 稀有度、收藏信息与美术素材。

统一撤离公式：

`normal_refund = floor(current_deployment_paid_cost × effective_refund_ratio)`，其中 `effective_refund_ratio` 优先读取卡牌字段，未配置时按 `cost` 档位表取得。

统一 CD 规则：

`normal_withdrawal_cd = max(1, card.redeploy_cd_base)`  
`rapid_withdrawal_cd = max(0, normal_withdrawal_cd - card.rapid_withdrawal_cd_reduction)`  
`normal_refund_ratio = card.normal_withdrawal_refund_ratio ?? refund_ratio_by_cost(card.cost)`

测试卡可以把 `normal_withdrawal_refund_ratio=0.5`、`redeploy_cd_base=1`；正式卡可以在同一规则字段中设置不同值。两者没有不同的撤离算法。

## 15. 必须通过的规则测试

1. 普通撤离不能选择非己方控制者、对方半区单位、眩晕单位或冰冻单位；非法动作不改变状态。
2. `slow`、`grounded`、`taunt` 默认不禁止普通撤离。
3. 快速撤离可以撤离冰冻/眩晕的己方单位；按本版建议也可从对方半区回收；不能撤离敌方控制单位。
4. 其他强制撤离效果只有显式设置豁免字段才可绕过控制/半区限制。
5. 普通退款按实际部署支付费用和卡牌退款比例向下取整；快速撤离全额返还实际支付费用；不可重复退款。
6. 撤离重置 HP、ATK、SP、护盾、临时状态和装备；但保留卡实例身份、部署历史、生命周期标记及 CD。
7. 没有全局再部署次数上限；多个卡实例可在同一行动阶段调度；单张卡实例须遵守自己的 CD。
8. 普通撤离 CD 至少为 1 个后续己方行动阶段；快速撤离减少 CD，最低为 0；撤离所在行动阶段不计入 CD。
9. 每次成功首次部署/再部署均触发一次 `on_deploy`；非法部署不触发。
10. 部署触发重复产费的净经济可被日志统计；程序安全阀不应被误当作卡牌平衡限制。
11. 冰冻期间所有 SP 获取来源均失效；眩晕不封锁 SP；受击反应先支付 SP，再处理本次攻击的 SP 回复。
12. 受击与受伤严格区分；护盾完全吸收时可触发 `on_attacked`，不能触发 `on_damaged`。
13. 嘲讽、拦截资格、浮空、落地、眩晕、冰冻的目标选择组合符合第 9、10 节。
14. 普通攻击每次伤害后立即结算阵亡，下一名攻击者重新选择目标；过量伤害默认不溢出。
15. 相同随机种子和相同动作序列可复现；至少 1000 局自动模拟无崩溃、非法状态或无限自动触发链。
16. 标准棋盘 `standard_3x1x1` 与 v0.7 旧版三路前后各一格的攻击顺序和目标结果保持一致（除本版明确修正规则外）。
17. 2路、3路、4路及前排多卡位棋盘均可创建、部署、战斗和结算；不得访问不存在的卡位。
18. 多卡位攻击顺序按 lane_order → front/back → slot_index；前排1号优先于同排2号；多个嘲讽目标按相同稳定规则排序。
