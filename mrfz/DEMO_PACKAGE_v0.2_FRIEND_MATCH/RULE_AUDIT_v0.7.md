# 三路攻防卡牌游戏规则漏洞审查与修改建议 v0.7

本文件配套 `GAME_RULES_v0.7.md`。v0.7 的目标不是再增加通用机制，而是让撤离、再部署、状态、技力和部署触发在同一套规则中闭环。

## 1. 本次已明确修正

| 优先级 | 问题 | v0.7 处理 | 仍需关注 |
|---|---|---|---|
| P0 | 受控干员仍可普通撤离，等于免费解控 | 普通撤离检查 `blocks_normal_withdrawal`；Stun/Freeze 禁止 | 未来控制状态必须明确该字段 |
| P0 | 对方半区的己方单位可被普通撤离 | 普通撤离要求 `board_half == controller_id` | 强制撤离按卡牌豁免配置 |
| P0 | Demo 与正式版 CD/退款分别判定，造成规则分叉 | 使用同一公式，卡牌配置不同数值 | 不允许引入 `is_demo` 条件分支 |
| P0 | 撤离重置后 CD 被误清零 | CD 属于卡实例生命周期元数据 | 回归测试撤离后 CD 保留 |
| P0 | 撤离后可重复领取同一次退款 | 退款前读取当前部署支付快照，结算后清除 | 对免费部署与折扣部署测试 |
| P0 | 撤离后状态重置也可能清除一次性标记 | 一次/每局标记默认属于生命周期元数据 | 卡牌需声明哪些标记随撤离重置 |
| P0 | 同一回合多次再部署被全局次数限制 | 不设全局次数上限 | 单卡 CD 和费用构成约束 |
| P0 | `on_deploy` 被默认每回合限次 | 每次成功入场触发一次 | 卡牌设计审查重复收益 |
| P1 | 快速撤离绕过控制与半区规则不明确 | 快速撤离显式豁免控制与半区；其他效果逐项配置 | 这是高强度效果，测试其卡牌机会成本 |
| P1 | 撤离被误判为死亡 | 单独触发 `on_leave_field`，不触发 death/kill | 召唤物和装备离场处理一致 |
| P1 | 护盾承伤与实际 HP 受伤混为一谈 | 分开 `on_attacked` 与 `on_damaged` | SP 回复时机测试 |
| P1 | 过量伤害与多段攻击目标重选不清 | 单次攻击过量伤害消失；下一攻击重新选目标 | 多段技能逐段锁定/重选必须写明 |

## 2. 重要平衡风险

### 2.1 撤离完全重置的价值过高

撤离会回满 HP、恢复 SP、清除控制和临时负面状态、移除装备。其价值相当于“治疗 + 回满技力 + 解控 + 状态清理 + 位置/路线重调”。

建议：
- 普通撤离退款比例与 CD 一起调，不要只看返还费用。默认退款比例按 cost 档位取 1/2、1/3、1/4、1/5；卡牌字段可在 0.20–0.50 区间覆写。
- 普通撤离必须受控制/半区限制，防止危险状态下免费脱身。
- 快速撤离作为消耗手牌的强力解围工具，应保留较大的卡牌机会成本。
- 普通撤离的退款默认按费用档位取 1/2、1/3、1/4、1/5，单卡可在 0.20–0.50 区间覆写；测试卡将参数统一配置为 0.50，不应为测试模式另写公式。
- 不要让撤离重置 `once_per_game` 或 `once_per_match` 触发标记，除非卡牌明确指定。

### 2.2 部署触发反复产费

重复触发 `on_deploy` 是核心机制，不应使用全局限次破坏它。但高退款、低 CD、低 cost 和产费效果组合可能形成净正收益循环。

每次循环计算：

`net_cost = redeploy_paid_cost - withdrawal_refund - on_deploy_cost_gain`

还要统计非费用价值：伤害、抽牌、治疗、护盾、SP、召唤、控制。即使 `net_cost=0`，若其他价值可反复累积，也可能失衡。

建议的平衡工具顺序：
1. 提高该卡 `redeploy_cd_base`；
2. 降低该卡 `normal_withdrawal_refund_ratio`；
3. 调整部署 cost；
4. 降低 `on_deploy` 收益；
5. 若单卡确实需要，再在卡面明确标注 `once_per_turn` 或每局次数限制。

不要把事件深度 32 的程序保护当作玩家可重复操作的经济限制。

### 2.3 快速撤离的强度

快速撤离为 0 cost、消耗一张手牌、全额返还最近一次部署费用、减少 1 点 CD，并且本版允许绕过控制与半区限制。它实际上兼具全额退款、解控、急救、SP 恢复和战术回收能力。

建议：
- 先保留 0 cost 以验证其手牌机会成本；
- 暂定每张牌只处理一个己方干员；
- 不附带抽牌或回收自身的能力；
- 任何复制、回收、生成快速撤离的效果都列为高风险组合；
- 通过使用率、获胜率、每次使用节省的 cost/CD、被控目标回收率评估。

如发现强度过高，优先调整卡牌出现频率/构筑数量或 CD 缩减量，不必改变普通撤离机制。

## 3. 需要在程序层严格分离的数据

建议将卡实例状态拆为：

- `IdentityState`：`card_instance_id`、`owner_id`、`controller_id`、`has_deployed_before`。
- `CombatState`：`current_hp`、`current_atk_modifiers`、`current_sp`、`shield`、`statuses`、`equipment_ids`、临时效果。
- `LifecycleState`：`redeploy_cd_remaining`、`current_deployment_paid_cost`、`once_per_game_flags`、`deployment_history`。
- `PositionState`：`board_half`、`lane`、`position`。

撤离重置只重置 `CombatState`，清理装备并更新 `LifecycleState` 的 CD/退款快照；不重置身份和生命周期标记。

## 4. 尚需重点测试的边界

| 场景 | 期望行为 |
|---|---|
| 冰冻干员普通撤离 | 拒绝，状态完全不变 |
| 冰冻干员使用快速撤离 | 允许，消耗战术卡、全额退款、清状态、按 CD 规则处理 |
| 对方半区己方干员普通撤离 | 拒绝 |
| 对方半区己方干员使用快速撤离 | 按 v0.7 建议允许；若后续决定不允许，只改该卡 `ignore_half_restriction` |
| 普通撤离后在同一回合结束时递减 CD | 不允许；用 `redeploy_cd_applied_owner_turn_index` 排除设置 CD 的当前回合 |
| 目标受击反应杀死攻击者 | 已提交攻击仍继续结算，除非反应明确写 `cancel_attack` |
| 目标在攻击伤害前因反应离场 | 当前攻击失去目标，不自动转移；下一名攻击者重新选目标 |
| 干员同回合多次快速撤离/再部署后重复普通攻击 | `entered_battle_this_owner_turn` 在撤离重置时保留，直到该玩家下回合开始才清零 |
| CD 在撤离当回合的 turn_end 被提前递减 | 使用 `redeploy_cd_applied_owner_turn_index` 排除设置 CD 的当前玩家回合 |
| 冰冻干员被快速撤离时触发自己的离场反应 | 冻结默认封锁该单位自身的事件型 `on_leave_field`；外部效果仍完成移除和重置 |
| 其他强制撤离没有豁免字段 | 不能绕过控制或半区限制 |
| 普通撤离后重复请求退款 | 不允许；部署支付快照已清除 |
| 同一干员同回合快速撤离并重新部署 | CD=0 时允许；重新支付 cost，重新触发 `on_deploy` |
| 同一干员连续普通撤离 | 第一次设置 CD；CD 未归零前不能重新部署，因此不能再次撤离 |
| 不同干员同一回合连续撤离 | 允许，无玩家级次数限制 |
| 撤离后原生浮空 | 保留；临时 grounded 清除 |
| 撤离后装备 | 解除并进入弃牌堆，不跟随返回手牌 |
| 撤离后 once_per_game 标记 | 保留，不因重置战斗状态而恢复 |
| 冰冻单位获得外部 SP | 增益无效，不延迟补发 |
| 护盾完全吸收攻击 | 触发 on_attacked/受击 SP，不触发 on_damaged/受伤 SP |

## 5. 版本统一建议

Demo 与完整版本使用同一规则文件、同一动作接口、同一状态判定和同一效果结算顺序。仅使用不同卡牌数据、卡池规模、牌组配置和视觉素材。不得在逻辑代码中出现 `if (isDemo)` 来改变撤离、CD、SP、战斗或状态规则。

测试卡可以统一使用 `normal_withdrawal_refund_ratio=0.5`、`redeploy_cd_base=1` 等容易观察的参数；正式卡池可以给不同卡配置不同数值。这样测试环境与正式环境只是在参数和内容上不同，不会发生玩法规则分叉。
