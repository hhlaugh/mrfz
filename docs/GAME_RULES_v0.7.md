# 三路攻防卡牌游戏规则 v0.7

> **文档状态：统一规则基线，待实现与平衡测试**  
> **替代版本：v0.6**  
> **本版原则：Demo 与正式版使用完全相同的规则引擎与判定逻辑。卡池规模、牌组数量、卡牌参数和美术资源可以不同，但不得设置 Demo 专属的战斗规则分支。**

## 0. v0.7 变更摘要

1. 普通撤离只能选择：当前玩家控制、位于当前玩家半区、且没有禁止普通撤离的控制状态的己方干员。
2. 被眩晕、冰冻或其他设置了 `blocks_normal_withdrawal=true` 的控制状态影响时，不能普通撤离。必须通过明确允许强制撤离的战术卡或效果移出战场。
3. 普通撤离的半区限制只约束普通撤离。战术卡或效果是否能跨半区撤离，必须由对应效果字段明确规定。
4. 普通撤离、快速撤离和效果型撤离使用同一套卡实例生命周期、状态重置及 CD 规则；区别仅由退款策略、CD 修正和限制豁免字段决定。
5. 删除“Demo 固定 CD=1、正式版另算”的规则分支。每张干员卡通过 `redeploy_cd_base` 配置基础 CD；测试卡与正式卡可填不同数值，但使用相同算法。
6. 删除“Demo 固定退款 50%、正式版另算”的规则分支。统一使用 `normal_withdrawal_refund_ratio`；当前测试卡可设为 0.5，正式卡可按费用、职业和角色强度配置 0.2–0.5。
7. 撤离后干员的战斗状态恢复到卡牌定义的初始状态；卡实例身份、部署历史及再部署 CD 等生命周期元数据保留。
8. 部署触发效果每次成功进入战场均触发，不设置全局或默认的每回合触发次数上限。重复部署套利由费用、退款、CD 和卡牌效果数值共同平衡。
9. 保留无全局再部署次数上限；同一行动阶段可以多次撤离和再部署，但每次重新进场均须满足该卡实例 CD。

## 1. 核心目标与术语

玩家通过部署干员、使用战术卡、装备支援、发动技能和调整阵线，争夺左、中、右三条路线，摧毁敌方基地。

| 中文标准术语 | 英文/代码 | 定义 |
|---|---|---|
| 基本分 | Base Points / `base_points` | 玩家基地耐久；降至 0 或以下即失败 |
| 生命值 | HP / `hp`, `current_hp` | 干员生命；不用于表示基地耐久 |
| 攻击力 | ATK / `atk`, `current_atk` | 干员攻击数值 |
| 费用 | Cost / `cost` | 玩家公共资源；卡牌印刷费用也用此字段 |
| 实际支付费用 | Paid Deploy Cost / `current_deployment_paid_cost` | 最近一次部署实际扣除的费用，作为撤离退款基数 |
| 技力 | SP / `current_sp` | 干员个人技能资源 |
| 行动阶段 | Action Phase / `action` | 部署、使用卡牌、技能及撤离的阶段 |
| 战斗阶段 | Combat Phase / `combat` | 当前回合玩家的干员自动普通攻击阶段 |
| 普通撤离 | Normal Withdrawal / `normal_withdrawal` | 玩家在行动阶段执行的基础撤离操作 |
| 快速撤离 | Rapid Withdrawal / `rapid_withdrawal` | 0 费战术卡；全额返还部署费用并减少此次撤离 CD |
| 强制撤离 | Forced Withdrawal / `forced_withdrawal` | 由明确的卡牌或效果执行，可按字段豁免普通撤离限制 |
| 再部署冷却 | Redeploy CD / `redeploy_cd_remaining` | 卡实例尚需跳过的后续己方行动阶段数 |
| 嘲讽 | Taunt / `taunt_scope` | 提高合法攻击者对指定嘲讽单位的普通攻击目标优先级 |
| 浮空 | Floating / `floating` | 后排专属原生词条；近战普通攻击不能选中，不拦截基本分攻击 |
| 落地 | Grounded / `grounded` | 暂时取消浮空，使其作为后位地面单位参与目标选择 |
| 眩晕 | Stun / `stun` | 禁止普通攻击和主动技能，并失去拦截资格 |
| 冰冻 | Freeze / `freeze` | 更强控制；封锁事件型技能与所有 SP 获取，并失去拦截资格 |
| 拦截资格 | Interception Eligibility / `intercept_eligible` | 根据位置及状态实时计算的结果，不是可任意设置的基础属性 |
| 所属半区 | Board Half / `board_half` | 干员当前所在棋盘半区 |

**字段区别必须保持：** `cost` 是卡牌印刷费用；`current_deployment_paid_cost` 是本次部署实际支付费用；`sp_cost` 是技能消耗的技力。三者不得混用。

## 2. 棋盘与部署

```text
                     A 玩家基地（基本分 20）
             A 后位： [左路]      [中路]      [右路]
             A 前位： [左路]      [中路]      [右路]
             ===================================== 中央战线
             B 前位： [左路]      [中路]      [右路]
             B 后位： [左路]      [中路]      [右路]
                     B 玩家基地（基本分 20）
```

- 双方各有左、中、右三路；每路各有前位和后位。
- 每名玩家每路前位、后位各一个部署位，最多同时部署 6 名干员。
- 前位靠近中央战线，后位靠近己方基地；位置名称始终相对控制者。
- 近战干员默认只能部署前位；远程干员默认只能部署后位；特种干员或具有特殊部署技能的干员可依卡牌 `deploy_rule=front_or_back` 获得前排部署资格。（2026-11-03 修订）
- 原生浮空干员只能部署后位；浮空不增加部署格。
- 当前普通攻击类型定义为 `melee` 与 `ranged`。若未来新增 `special`，必须给该干员提供独立且明确的普通攻击目标算法；没有目标规则的 `special` 干员不能执行普通自动攻击。
- MVP 不使用传统数值型阻挡数 `block`。当前对局通过“拦截资格”判断普通攻击是否先攻击干员而非基本分。
- `owner_id`、`controller_id`、`board_half` 分别记录所有者、当前控制者和所在半区；MVP 暂不实现夺取控制权，但字段保持分离。
- `attack_type` 当前正式攻击类型只定义 `melee` 与 `ranged`。若将来增加 `special`，必须为该卡明确提供目标选择算法；没有目标规则的 `special` 单位不能执行普通自动攻击。

## 3. 牌组与开局

- 标准构筑目标为每套 30 张，同名卡最多 2 张。
- Demo 或测试牌组可以使用较小固定牌组验证系统，但这只是测试卡池/牌组配置，不改变任何卡牌、回合、撤离、战斗或状态规则。
- 首发完整卡池规划为 144 种不同卡牌：72 张干员、48 张战术、24 张支援。卡牌稀有度用于收藏和抽卡，不自动增加战斗属性。
- 双方选择牌组并洗牌，基本分设为 20，费用设为 0。
- 双方各抽 5 张起手牌。
- 双方各进行一次起手换牌：选择 0–5 张放入暂存区，从牌库抽取相同数量的新牌，再将暂存卡洗回牌库。起手换牌不触发疲劳；双方均完成后随机决定先手。
- 随机决定先手后，回合严格交替：A→B→A→B，不会出现同一玩家连续获得完整行动回合。

## 4. 费用、抽牌与疲劳

### 4.1 费用

- 当前玩家每个己方回合开始获得 3 点费用，费用上限为 10。
- 未使用费用保留；获得费用超过上限的部分舍弃。
- 部署、战术、支援和装备按各自 `cost` 支付；效果可以减免或增加费用，但最终费用不能低于 0。
- 每次成功部署必须记录实际支付费用，含折扣后的真实数值。
- 所有动作必须先校验阶段、目标、位置、状态、CD 和费用，再原子提交。非法动作不得部分扣费、移牌或触发效果，并应向玩家显示原因。

### 4.2 抽牌与疲劳

- 每名玩家在自己回合开始时抽 1 张牌。
- 手牌上限建议为 10。手牌已满时，若牌库仍有牌，抽到的牌进入弃牌堆；这不算抽牌失败，也不产生疲劳。
- 每当规则要求抽牌而牌库为空，产生一次疲劳：该玩家第一次失败抽牌造成 1 点基本分伤害，第二次 2 点，第三次 3 点，依此递增。双方疲劳计数独立且不重置。
- 抽多张牌时逐张处理，每次空抽分别增加疲劳伤害。
- 疲劳伤害不受干员护盾和普通减伤影响，除非卡牌明确写明。
- 弃牌堆默认不自动洗回牌库；洗回效果不会重置疲劳计数。
- 撤离返回手牌不受手牌上限限制，不会因此丢弃。

## 5. 回合结构

每名玩家回合固定四阶段：`turn_start → action → combat → turn_end`。

### 5.1 回合开始 `turn_start`

执行顺序：
1. 重置己方每回合限次标记（不包含再部署次数计数；本规则没有全局再部署次数上限）。
2. 获得 3 点费用（不超过上限）。
3. 抽 1 张牌；空抽则按疲劳规则结算。
4. 结算 `turn_start` 触发效果。
5. 己方场上每名未冰冻干员按 `sp_regen_per_turn` 回复 SP，默认 +1；冰冻干员不获得 SP。
6. 检查胜负，未结束则进入行动阶段。

回合开始时的 SP 回复只作用于当时已在场的干员；在本回合行动阶段新部署的干员不会追溯获得本次自然回复。冻结期间所有来源的 SP 增加均被阻止，详见第 10 节。

### 5.2 行动阶段 `action`

玩家可按任意顺序、重复执行合法操作，直到主动结束行动阶段：

- 首次部署或再部署干员；
- 使用战术卡；
- 打出支援设施或装备；
- 发动己方干员主动技能；
- 普通撤离；
- 使用快速撤离或其他强制撤离效果。

本规则不限制行动阶段的撤离/再部署次数。相同干员能否重新进入战场只由该卡实例的 `redeploy_cd_remaining`、费用、部署位置与效果限制决定。多个不同干员可在同一行动阶段内依次调度；同一干员也可在 CD 为 0 时于同一行动阶段再次部署。

玩家可在部署、战术、技能和撤离操作之间自由交替。结束行动阶段后不能再主动执行这些操作，除非卡牌明确规定在战斗阶段或其他阶段使用。

本回合行动阶段任何时候进入战场的干员，默认不能参加本回合普通攻击；但若其 SP 足够，可以在行动阶段发动主动技能。其被动和反应技能按各自状态和触发规则处理。程序需记录 `entered_battle_this_owner_turn`：本回合首次部署/再部署时设为 true，撤离重置不得清除；在该玩家下一个回合开始时重置为 false。这样同一回合内快速撤离、反复再部署不会获得额外普通攻击。

**不设置行动阶段现实时间限制，也不设置玩家级再部署次数上限。** 自动触发链另有程序安全阀，不能把安全阀当作玩家操作次数限制。

### 5.3 战斗阶段 `combat`

- 只有当前回合玩家控制的干员进行普通攻击；对手干员不会因此进行普通攻击。
- 对手干员仍可触发符合状态限制的被动、反应和防御效果。
- 每名符合条件的己方干员每个己方战斗阶段默认进行一次普通攻击；追加攻击必须由卡牌明确规定。
- 路线按左→中→右结算，每路先前位攻击者、再后位攻击者。
- 每次攻击后立即结算伤害、护盾、阵亡、SP 和触发效果；下一名攻击者重新选择目标。

### 5.4 回合结束 `turn_end`

1. 结算己方 `turn_end` 效果。
2. 更新持续状态与持续效果时间。
3. 对该玩家拥有的、在本次撤离后需要跳过己方行动阶段的卡实例，按 CD 规则递减冷却。
4. 检查双方基本分；未结束则切换玩家。

持续时间按状态定义的拥有者回合计算。一个状态若在目标本次回合中途施加，不会在同一回合结束时被错误地提前扣除完整持续时间。

## 6. 普通撤离、快速撤离与强制撤离

### 6.1 普通撤离的合法条件

普通撤离是行动阶段的基础操作，不消耗手牌。目标必须同时满足：

1. 是当前玩家控制的己方干员；
2. 当前位于当前控制者自己的半区，即 `board_half == controller_id`；
3. 当前没有任何 `blocks_normal_withdrawal=true` 的状态；本规则初始将 `stun`、`freeze` 配置为禁止普通撤离；
4. 当前在战场上。

因此，处于眩晕或冰冻状态、或被位移到对方半区的己方干员，均不能被普通撤离。`slow`、`grounded`、`taunt` 默认不禁止普通撤离。未来新增控制状态必须明确配置是否阻止普通撤离，不能仅凭名称推断。

普通撤离次数没有上限，但每次撤离都会给该卡实例设置再部署 CD。玩家可以连续撤离不同干员；同一干员只有在 CD 归零后才能再次部署。

### 6.2 普通撤离退款

统一公式：

`refund = floor(current_deployment_paid_cost × effective_refund_ratio)`

其中 `effective_refund_ratio = card.normal_withdrawal_refund_ratio`；若卡牌未配置该字段，则使用费用档位默认值：cost 1–2 = 0.50，3–4 = 1/3，5–6 = 0.25，7+ = 0.20。

- `normal_withdrawal_refund_ratio` 是卡牌数据参数，建议合法区间为 0.20–0.50；未设置时采用上述费用档位默认值。测试卡可统一配置 0.50，完整卡池可按费用、职业和角色强度覆写，但不改变公式。
- 退款基于最近一次实际支付费用，而非印刷 `cost`。
- 免费部署的实际支付费用为 0，撤离退款为 0。
- 退款受玩家费用上限影响，超额部分舍弃。
- 退款先读取并结算，随后清除本次部署的支付记录，避免同一次部署被重复退款。

### 6.3 快速撤离 `rapid_withdrawal`

- 快速撤离是一张 `cost=0` 的战术卡，在行动阶段打出并消耗该手牌。
- 成功时，将目标己方干员返回手牌，返还其最近一次部署的全部实际支付费用，并将本次撤离产生的 `redeploy_cd_remaining` 减少 1，最低为 0。
- 快速撤离明确属于战术强制撤离，因此允许撤离处于 `stun`、`freeze` 等禁止普通撤离状态的己方干员。
- **本版建议：快速撤离同时允许回收位于对方半区的己方干员**，因为半区限制只约束普通撤离；目标仍必须由当前玩家控制，不能选择敌方控制的单位。此设定应作为快速撤离卡牌文本的一部分，而不是所有战术卡自动拥有的能力。
- 快速撤离消耗一张手牌，即使其费用为 0，也有手牌机会成本。
- CD 降为 0 后，只要当前仍处于行动阶段且其他部署条件满足，该干员可以立即重新部署；重新部署仍支付新一次部署费用并重新触发 `on_deploy`。

### 6.4 其他效果型/战术型强制撤离

- 任何战术卡或技能效果都可以在其文本和数据中定义返回手牌/强制撤离。
- 普通撤离限制不会自动套用到强制撤离；但强制撤离也不会自动绕过全部限制。每个效果必须明确配置 `ignore_control_restriction`、`ignore_half_restriction`。
- 未明确豁免时，强制撤离默认仍不能移除被控制或位于对方半区的单位；快速撤离作为本规则中特别定义的卡牌，明确豁免这两项。
- 效果型强制撤离的退款策略必须明确写为 `none`、`normal_ratio`、`full_paid_cost` 或固定数值；默认 `none`。
- 效果型强制撤离的 CD 默认使用该干员的 `redeploy_cd_base`；卡牌可明确增减 CD。
- 强制撤离不会触发死亡、友方阵亡或击杀；会触发 `on_leave_field`。

### 6.5 撤离后的战斗状态重置

普通撤离、快速撤离以及明确写明“返回手牌并重置”的强制撤离，成功后将干员战斗状态恢复到当前卡牌定义的初始状态：

- `current_hp = hp`；
- `current_atk` 及其他可计算战斗属性恢复为卡牌基础值；
- `current_sp = starting_sp`；
- 护盾归零；
- 清除所有临时增益、减益、眩晕、冰冻、减速、临时落地、临时嘲讽及其他战斗状态；
- 附着装备解除，装备卡进入拥有者弃牌堆；装备产生的数值修正随之移除；
- 原生卡牌词条（例如原生 `floating`、基础嘲讽）保留；
- 卡实例身份、所有者/控制者、`has_deployed_before`、生命周期标记、`entered_battle_this_owner_turn` 及 `redeploy_cd_remaining` 保留；
- 退款在重置前读取 `current_deployment_paid_cost`；处理完毕后清除该次支付快照。再次部署时写入新的实际支付费用。

撤离不算阵亡；不会触发 `on_death`、`on_ally_death` 或 `on_kill`。撤离也不会清除再部署 CD 或一次性/整局使用标记，除非卡牌明确写明重置。

### 6.6 CD 的设置与计时

- 每张干员卡定义 `redeploy_cd_base`，表示普通撤离后需要跳过的后续己方行动阶段数；普通撤离最低为 1。
- CD 属于卡实例生命周期元数据，不因战斗状态重置而清零。
- 每次正常撤离或未特别修改 CD 的强制撤离，将 `redeploy_cd_remaining` 设为该卡的 `redeploy_cd_base`。
- 快速撤离将这次 CD 减少 1，最低为 0。
- CD=0 时，只要当前仍处于行动阶段且其他条件满足，就可以重新部署；CD>0 时不能部署。
- 撤离发生的当前行动阶段不计入 CD。每经过一个后续的己方行动阶段，在该行动阶段结束时减少 1；当 CD 归零后，从之后的可执行动作时机起允许部署。
- 实现时必须记录 `redeploy_cd_applied_owner_turn_index`（设置 CD 时的卡牌控制者回合序号），只允许在序号更大的后续己方回合结束时递减，避免撤离当回合结束时错误扣除 CD。
- 不使用现实时间、对手回合或双方完整轮次计时。
- 全局再部署次数没有上限，不存在 `redeploys_used_this_turn` 或同义玩家级计数器。

**卡牌 CD 配置建议（用于生成卡牌初始数值，不是第二套模式规则）：**

| 印刷 cost | 建议基础 CD |
|---:|---:|
| 1–2 | 1 |
| 3–4 | 2 |
| 5–6 | 3 |
| 7+ | 4 |

职业修正候选：先锋 -1、特种 -1、重装 +1，其余职业 0；最终值建议限制在 1–5，并允许卡牌级覆盖。此表需与退款比例、部署触发收益共同进行模拟调整。当前测试卡只是在同一字段中填写较简单的数值，不拥有不同的规则逻辑。

## 7. 部署触发与重复收益

- 每次干员成功从手牌进入战场（首次部署或再部署）均触发一次 `on_deploy`。
- 不设置默认的每实例每回合部署触发上限，也不限制玩家回合内的部署/撤离操作次数。
- 每次成功部署事件内，同一触发器默认执行一次；只有卡牌明确声明多段触发才执行多次。
- 位置非法、费用不足、CD 未归零、目标非法时部署失败：不扣费、不移牌、不改变实例状态、不触发 `on_deploy`。
- 部署触发获得费用、SP、造成伤害、治疗、召唤等效果均可重复触发；这属于游戏的调度构筑机制。
- 每个根事件自动触发链设置最大深度 32，防止程序递归故障。该安全阀不限制玩家主动操作数量，也不能代替卡牌平衡。
- 卡牌审查必须计算循环净费用：`net_cost_per_cycle = redeploy_paid_cost - withdrawal_refund - on_deploy_cost_gain`。若净费用 ≤0，且重复部署能继续造成伤害、抽牌、治疗、护盾或其他可累计收益，则属于高风险循环，必须通过卡牌 CD、退款比例、部署费用或效果强度调整，而不是默认禁止重复部署触发。
- `once_per_turn`、`once_per_game` 等限制只在卡牌明确声明时使用，撤离重置不得自动清除这些生命周期标记。

## 8. 技力 SP 与技能

### 8.1 SP 资源

- 每名干员独立拥有 `current_sp`、`max_sp`、`starting_sp`。
- 默认 `max_sp=5`、`starting_sp=0`；每名干员可以单独配置。
- 默认每个己方回合开始自然回复 +1 SP；特殊干员可以将 `sp_regen_per_turn` 设为 0，改由受击、受伤、击杀或其他效果获得 SP。
- `sp_gain_on_attacked`：成为一次有效攻击目标后获得 SP；即使护盾完全吸收，只要攻击确实命中目标，仍属于受击。
- `sp_gain_on_damaged`：实际 HP 减少后获得 SP；护盾完全吸收不触发。
- `sp_gain_on_kill`：某干员作为可识别来源使敌方干员阵亡后获得 SP，默认建议 +1；范围效果/单个根攻击事件的击杀奖励总量可由卡牌/规则参数设置上限，建议初始为 2。
- 战术卡或支援效果直接增加 SP，使用统一 `gain_sp` 入口。
- SP 不能低于 0 或超过 `max_sp`；溢出部分舍弃。手牌、牌库和弃牌堆中的干员不获得 SP。

### 8.2 冰冻期间 SP 封锁

- 冰冻期间任何来源的 SP 增加全部失效：自然回复、受击、受伤、击杀、友方辅助、支援、装备、战术卡和其他技能效果均不能增加 SP。
- 被封锁的 SP 不排队、不延迟、不在解冻后补发；已有 SP 保留。
- 眩晕不封锁 SP 获取。

### 8.3 技能类型

- 主动技能 `active`：当前玩家在行动阶段主动发动，消耗 `sp_cost`；被冻结或眩晕的干员不能发动。
- 条件被动 `passive_free`：满足条件自动生效，不消耗 SP。
- 技力被动 `passive_sp`：满足事件条件时，若 SP 足够则先扣 SP 再发动；不足则本次不发动、不排队。
- 反应技能 `reaction_sp`：受到攻击、实际受伤、友方阵亡等事件触发，可在非拥有者回合自动发动；按状态和 SP 条件判断。
- 主动、技力被动、技力反应共用同一干员 SP 池。
- 同一事件触发多项自动技力技能时，按 `skill_priority` 从高到低检查；同优先级按稳定卡实例顺序。
- 受击反应在伤害结算前检查和支付 SP；本次攻击产生的受击/受伤 SP 回复在攻击伤害与相关死亡结算之后处理，不能反过来支付同一次攻击的前置反应技能。

## 9. 自动战斗与目标选择

### 9.1 攻击队列

- 按左路→中路→右路；每路当前玩家前位干员先攻击，再由后位干员攻击。
- 轮到攻击者时，重新检查其是否存活、是否处于控制状态、是否为本回合新部署、是否已攻击。
- 新部署/再部署干员默认不参加本回合普通攻击；卡牌明确允许立即攻击时例外。
- 战斗阶段中通过效果新召唤的干员默认不加入当前普通攻击队列。

### 9.2 拦截资格

`intercept_eligible` 是运行时派生值。干员必须同时满足：在场、地面状态、未眩晕、未冰冻。前位和后位都可能具有拦截资格；若前位失去拦截资格，后位地面干员可以成为下一合法目标。浮空单位不拦截基本分攻击；落地的浮空单位按后位地面干员处理。

### 9.3 默认目标优先级

每次普通攻击开始时重新选择目标：

1. 同一路合法嘲讽目标（攻击者必须具备攻击该目标的能力）；
2. 同一路有效地面前位干员；
3. 同一路有效地面后位干员；
4. 若攻击者为远程，选择同一路可被远程攻击的有效浮空干员；
5. 没有合法干员目标时，攻击敌方基本分。

说明：
- 嘲讽可以覆盖普通前后位优先级，但不能让攻击者攻击本来无法选中的目标；近战不能因嘲讽而攻击浮空单位。
- 多个合法嘲讽目标同时存在时，优先前位；同位置再按卡牌规则或稳定实例顺序确定。
- 眩晕/冰冻单位失去拦截资格，且不作为默认普通攻击目标；若整路所有干员均处于眩晕/冰冻等不可作为普通攻击目标的状态，则攻击者直接攻击基本分。
- 若地面拦截单位均不存在，但有未受控制的浮空单位：近战攻击者不能攻击浮空单位，直接攻击基本分；远程攻击者优先攻击浮空单位，而不是直接攻击基本分。
- 卡牌可通过 `target_priority` 明确覆盖默认目标逻辑，但必须定义攻击者能否攻击该目标、是否忽略嘲讽及是否可攻击浮空。

### 9.4 单次攻击结算

1. 选择合法目标并建立攻击事件。
2. 检查目标的合法 `on_attacked` 反应；按技能优先级先支付 SP，再发动防御效果。
3. 应用攻击力修正、伤害增减益和减伤；伤害最低为 0。
4. 伤害先由护盾吸收，剩余伤害扣除目标 HP；攻击基本分时扣除 `base_points`。
5. 处理 `on_damaged`、濒死/防止阵亡、阵亡、击杀和 SP 获取。
6. 当前攻击事件及触发链完成后，下一名攻击者重新选择目标。

**攻击提交与反应时序：** 普通攻击一旦完成目标选择并进入攻击事件，即视为已提交。目标的反应可以减伤、加护盾、造成反伤或改变后续状态，但除非效果明确带有 `cancel_attack`，否则不能追溯取消已提交的攻击。若目标在伤害结算前因自身反应或其他效果离场，本次攻击失去目标并结束，不自动改打其他单位；下一名攻击者重新选目标。

过量伤害默认不溢出：目标剩余 2 HP、受到 6 点单体伤害时，该目标阵亡，超出 4 点消失；下一次独立攻击重新选择目标。穿透、溢出、多目标和多段攻击必须在卡牌中明确。

## 10. 状态效果

### 10.1 眩晕 `stun`

- 禁止普通攻击和主动技能；失去拦截资格；禁止普通撤离。
- 不封锁 SP 获取。
- 默认允许条件被动和满足条件的反应技能触发，除非技能另有限制。
- 原生浮空在眩晕期间暂时失效；眩晕结束后，若没有独立 `grounded` 状态则恢复浮空。
- 默认持续至目标下一次己方回合结束；具体卡牌可以配置持续时间。

### 10.2 冰冻 `freeze`

- 禁止普通攻击、主动技能、事件型被动和反应技能；持续被动属性/光环仍存在。
- 失去拦截资格；嘲讽失效；禁止普通撤离。
- 封锁所有来源的 SP 获取；已有 SP 不清零。
- 原生浮空在冰冻期间暂时失效；冰冻结束后，若没有独立 `grounded` 状态则恢复浮空。
- 普通伤害不会自动解除冰冻，除非卡牌明确规定。
- 默认持续至目标下一次己方回合结束；具体卡牌可以配置。

### 10.3 临时落地 `grounded`

- 只作用于原生具有 `floating=true` 的后位干员。
- 普通位移造成的临时落地默认持续 2 个目标所属玩家的己方回合；持续时间是可配置数值，未来通过平衡调整。
- 落地期间按后位地面干员处理，可被近战普通攻击选中；若未眩晕/冰冻则具有后位拦截资格。
- 眩晕/冰冻对浮空的暂时压制与 `grounded` 独立计时；控制结束后，如果 `grounded` 仍存在，继续按地面单位处理。
- 本规则版本不实现永久移除浮空、强力位移或精英化位移。
- 落地计时按目标拥有者自己的回合计算；状态施加所在回合不扣完整一回合，之后每结束一个目标己方回合减 1。

### 10.4 减速 `slow`

默认使目标下一次己方战斗阶段普通攻击力 -1，最低为 0。除非卡牌明确说明，不禁止主动技能、被动/反应、SP 获取、拦截或普通撤离。

### 10.5 护盾 `shield`

护盾先吸收 HP 伤害。被攻击但护盾完全吸收仍触发 `on_attacked` 和受击 SP 回复；不触发 `on_damaged` 和受伤 SP 回复。护盾持续时间按卡牌文本；未写明时保留至消耗或宿主离场。

### 10.6 状态叠加与冲突

- `freeze` 与 `stun` 同时施加时，控制效果不叠加成更高等级；保留剩余时间更长的冰冻，眩晕不额外延长冰冻。
- 同类状态再次施加，默认刷新为较长剩余时间，不叠加数值，除非卡牌明确允许。
- `grounded` 与 `stun`/`freeze` 独立计时；控制结束后若落地仍在，则继续落地。
- 持续被动属性和静态光环不会仅因冰冻而移除；冻结封锁的是事件型被动/反应和 SP 增加。

## 11. 支援、装备与卡实例生命周期

- 支援卡分设施 `facility` 和装备 `equipment`，都在行动阶段打出。
- 每方最多同时存在 2 个持续设施；每名干员默认最多附着 1 件装备，除非卡牌提高装备位。
- 撤离/阵亡时装备解除并进入拥有者弃牌堆；设施不因某名干员撤离而自动离场。
- 每张实体卡副本有独立 `card_instance_id`；同名副本的 HP、SP、CD、状态、部署历史和支付费用不共享。
- 撤离重置战斗状态，但不重置卡实例身份、`owner_id`、`controller_id`、`has_deployed_before`、`entered_battle_this_owner_turn`、生命周期标记、`redeploy_cd_remaining`。
- 任何“一次/每局”标记默认属于卡实例生命周期，不因普通撤离重置；只有卡牌明确说明才重置。

## 12. 效果事件与程序安全

标准事件名：`turn_start`、`turn_end`、`on_play`、`on_deploy`、`on_attacked`、`on_damaged`、`on_damage_survive`、`on_lethal`、`on_death`、`on_ally_death`、`on_kill`、`on_heal`、`on_leave_field`、`combat_end`。

- `on_attacked`（受到攻击）与 `on_damaged`（HP 实际下降）必须分开。
- `on_leave_field`（离场/撤离）与 `on_death`（阵亡）必须分开。
- `on_deploy` 每次成功进入战场触发一次，首次部署及再部署一致。
- 自动效果使用事件队列；单根事件触发深度设置 32 作为程序防递归安全阀，超出时记录错误并中止异常链。此阀不限制玩家主动部署、撤离或再部署次数。
- 冻结会封锁该单位的事件型被动/反应；因此被冻结单位自身的 `on_attacked`、`on_damaged`、`on_death`、`on_leave_field` 等事件技能默认不触发，但冻结不会阻止其他单位或全局效果处理该单位的阵亡、离场和状态清理。若卡牌明确写明“无视冰冻触发”，才可例外。
- 卡牌效果 JSON 只能使用白名单动作，不得执行任意代码。
- 每个效果需要明确定义触发时机、目标集合、SP 费用、目标合法性、持续时间、次数限制和失败行为。

## 13. 胜负判定

- 任一方 `base_points <= 0`，当前不可分割效果及必要触发链完成后判定胜负。
- 一方基本分归零，另一方获胜；同一不可分割效果同时令双方基本分归零，判为平局。
- 不设置固定回合上限；疲劳推动自然终局。若以后举办限时赛事，计时属于赛事规则，不改变基础游戏规则。
- 对局结束后不再执行后续攻击、动作或回合。

## 14. 统一规则与数据配置原则

Demo、内部测试和正式版本使用同一套规则逻辑。以下差别只能通过配置数据体现，不得写成互斥规则分支：

- 牌组张数、卡池规模与卡牌数量；
- 每张卡的 `cost`、`normal_withdrawal_refund_ratio`、`redeploy_cd_base`；
- 干员的 HP、ATK、SP 上限、起始 SP、SP 回复和技能消耗；
- 技能效果、状态持续时间、目标优先级；
- 稀有度、收藏信息与美术素材。

统一撤离公式：

`normal_refund = floor(current_deployment_paid_cost × effective_refund_ratio)`，其中 `effective_refund_ratio` 优先读取卡牌字段，未配置时按 `cost` 档位表取得。

统一 CD 规则：

`normal_withdrawal_cd = max(1, card.redeploy_cd_base)`  
`rapid_withdrawal_cd = max(0, normal_withdrawal_cd - card.rapid_withdrawal_cd_reduction)`  
`normal_refund_ratio = card.normal_withdrawal_refund_ratio ?? refund_ratio_by_cost(card.cost)`

测试卡可以把 `normal_withdrawal_refund_ratio=0.5`、`redeploy_cd_base=1`；正式卡可以在同一规则字段中设置不同值。两者没有不同的撤离算法。

## 15. 必须通过的规则测试

1. 普通撤离不能选择非己方控制者、对方半区单位、眩晕单位或冰冻单位；非法动作不改变状态。
2. `slow`、`grounded`、`taunt` 默认不禁止普通撤离。
3. 快速撤离可以撤离冰冻/眩晕的己方单位；按本版建议也可从对方半区回收；不能撤离敌方控制单位。
4. 其他强制撤离效果只有显式设置豁免字段才可绕过控制/半区限制。
5. 普通退款按实际部署支付费用和卡牌退款比例向下取整；快速撤离全额返还实际支付费用；不可重复退款。
6. 撤离重置 HP、ATK、SP、护盾、临时状态和装备；但保留卡实例身份、部署历史、生命周期标记及 CD。
7. 没有全局再部署次数上限；多个卡实例可在同一行动阶段调度；单张卡实例须遵守自己的 CD。
8. 普通撤离 CD 至少为 1 个后续己方行动阶段；快速撤离减少 CD，最低为 0；撤离所在行动阶段不计入 CD。
9. 每次成功首次部署/再部署均触发一次 `on_deploy`；非法部署不触发。
10. 部署触发重复产费的净经济可被日志统计；程序安全阀不应被误当作卡牌平衡限制。
11. 冰冻期间所有 SP 获取来源均失效；眩晕不封锁 SP；受击反应先支付 SP，再处理本次攻击的 SP 回复。
12. 受击与受伤严格区分；护盾完全吸收时可触发 `on_attacked`，不能触发 `on_damaged`。
13. 嘲讽、拦截资格、浮空、落地、眩晕、冰冻的目标选择组合符合第 9、10 节。
14. 普通攻击每次伤害后立即结算阵亡，下一名攻击者重新选择目标；过量伤害默认不溢出。
15. 相同随机种子和相同动作序列可复现；至少 1000 局自动模拟无崩溃、非法状态或无限自动触发链。
